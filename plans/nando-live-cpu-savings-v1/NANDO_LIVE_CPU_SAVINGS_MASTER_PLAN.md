## 10. Durability, Retention, And Restart

Every report and state transition is content addressed and crash atomic:

```text

-> temporary file
-> file fsync
-> atomic rename
-> directory fsync
-> immutable root / coherent latest pointer
```

Append-only ledgers and active generations must survive restart byte for byte.
Retention may never delete:

- an active or `PROBE_PENDING` generation;
- a precommitted prediction awaiting settlement;
- support/future rows referenced by a non-terminal root;
- a LawCertificate, cleanup, revocation, admission, execution, or economics
  receipt;
- an externally anchored ledger prefix;
- the active binary/config rollback set and deployment receipt.

Eligible raw provider payloads have bounded privacy retention. Derived
source-neutral commitments may outlive raw payloads; raw session content may
not be retained indefinitely merely because discovery is incomplete.

Cleanup is retryable and idempotent. A terminal event does not mark retention
complete until the durable cleanup receipt exists.
