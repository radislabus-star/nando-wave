## 10. Intent-First Cleanup Transaction

The cleanup owner receives only the governed root read-write, control root
append-only, authorization receipt and before descriptor. It rechecks its own
executable hash and each path identity.

Ordering:

```text
disposable regular files by path order
-> disposable empty directories by descending depth then path order
```

For each path:

```text
DELETE_INTENT_FROZEN
  temp write -> file fsync -> rename -> control-root directory fsync
-> revalidate no symlink and exact pre-delete identity
-> unlink or rmdir
-> governed parent directory fsync
-> DELETE_COMPLETE_FROZEN
  temp write -> file fsync -> rename -> control-root directory fsync
```

Restart rules:

```text
no intent                      no mutation allowed
intent + matching path         complete exact deletion
intent + path absent           freeze completion after parent census
intent + mismatched path       terminal failure
completion + path absent       continue
completion + path present      terminal failure
```

Broad recursive deletion, wildcard deletion, symlink traversal and deletion of
unlisted paths are forbidden. Cleanup failure preserves the terminal receipt
and never creates another rehearsal or authorization.
