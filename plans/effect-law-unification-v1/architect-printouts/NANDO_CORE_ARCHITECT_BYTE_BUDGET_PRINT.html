NANDA MACHINE / NANDO-WAVE
Северная звезда + исполняемая архитектура
Product loop + Grokking loop
Редакция: 2026-08-11 · Preregistered Grounded Meaning V1

Машина, которая выращивает
собственный язык действий

NANDA получает опыт, открывает в нём наблюдаемый переносимый закон, кристаллизует закон в проверяемый opcode и делает его частью языка следующего уровня. nando-wave — продуктовая реализация этого принципа для live-трафика и CPU-операторов; она не является cache и не подменяет исследовательскую цель одной экономией токенов.

Северная звезда: грокать всё, в чём существует наблюдаемый и переносимый причинный закон, а каждый доказанный закон превращать в строительный элемент следующего уровня.

01 / PRODUCT LOOP
Оплаченный опыт становится исполняемым активом

LLM учит один раз.
Проверенный закон остаётся у системы.

Продуктовый контур превращает повторяемое поведение агента не в transcript, prompt или cache-hit, а в детерминированный OperatorPackage. LLM может быть учителем и источником опыта, но после admission её нет ни внутри оператора, ни в hot path, ни в authority chain.

Продуктовая формула: NANDA превращает оплаченные рассуждения LLM в принадлежащий компании капитал действий: переносимый, детерминированный, проверяемый и исполняемый без повторного вызова модели.

02 / GROKKING LOOP
K1 исполняет · K2 проверяет смысл над действиями

Гроккинг — сердце.
CPU-экономия — проверяемое следствие.

Гроккинг здесь означает не выбор готового шаблона, а формирование компактного relation-circuit, который сохраняет закон после удаления exact episode memory и переносится на неизвестную поверхность. K2 начинается не с готового DAG, а когда переходы уже найденных K1-операторов становятся материалом для скрытого инварианта, выдерживающего новые реализации, вмешательства и композиции.

Следующий большой экзамен — K2 Grounded Meaning: три разных K1 law являются лишь минимальным базисом. Затем система должна построить representation над проверенными переходами и превзойти ID, retrieval, surface и typed-effect-algebra baselines на substitution, intervention и novel composition holdouts.

Антицели

cache hit                         != grokking
template selection                != law discovery
короткое имя длинной цепочки      != recursive intelligence
phase score без causal ablation   != understanding proof
скрытый вектор без transfer       != meaning
готовый CompositionDag            != K2 discovery
экономия токенов                  != scientific authority
LLM внутри hot operator           != CPU-native learned skill
Wave может ускорять поиск и кристаллизовать relation-circuit, но не подтверждает собственную гипотезу и не выдаёт authority.
02B / GROUNDED MEANING
Цель до действия · альтернативы · явная проверка

Смысл принадлежит решению,
а не вектору оператора

K1 уже несёт операционный смысл: когда действие применимо и какой точный эффект оно создаёт. Но state + action -> next state доказывает только динамику. K2 должен связать состояние, цель, допустимые альтернативы и проверенный исход, а затем перенести эту связь на новые реализации, вмешательства и композиции. 

durable actor + independent verifier receipts
-> GroundedTransitionEpisodeV1             ATOMIC FACT / DYNAMICS

pre-action TypedGoalContractV1
+ constraints + observation mask + frozen horizon
+ applicable K1 actions including ABSTAIN
+ selected action/sequence + verified goal satisfaction
-> GroundedDecisionEpisodeV1               UNIT OF K2 EVIDENCE
          |
          v
state z_s + goal z_g + action z_a + uncertainty u_t
-> predicted delta / satisfaction / target representation
-> model-induced equivalence m(state, goal, action, horizon)
-> explicit candidate -> identifier -> natural future
-> MetaSkillPackage -> verifier -> External Admission
Критическая граница: цель фиксируется до действия. Нет цели или значимой альтернативы — эпизод DYNAMICS_ONLY. Latent-координаты не являются meaning, law_id или runtime authority и не входят в BundleV4.

03 / CANONICAL OPERATOR IR
Один закон после разных путей обучения

Две дороги, один обязательный язык

Adaptive identification выбирает закон из известного version space. Circuit induction рождает новую связную topology из распределённых relation fragments. Их внутренние механизмы различны; downstream-истина едина.

Минимальный контракт IR

БлокСодержитИнвариант
Routingrole schema, signed phase relations, applicabilityТолько pre-action evidence
Executionguards, relation program, typed transforms, compositionBounded deterministic semantics
Outputrenderer and emission contractНикакого скрытого LLM-вызова
Verificationexpected consequence schemaActor не является verifier oracle

Что IR не содержит

raw traces / learner memory             OUT
exact episode lookup                    OUT
target patch / future action            OUT
live counters / economics               OUT
rollout percentage                      OUT
AuthorityLease                          OUT
mutable registry state                  OUT
source-specific family -> operator map  OUT
Эквивалентность: два learner-маршрута могут иметь разные routing phase и provenance, но обязаны сходиться к одной executable identity, если исполняют один и тот же закон. Маршрут не подменяет семантику действия.
Новый operator kind не должен требовать отдельной Rust-ветки после IR. Если compiler или VM не способны выразить закон, это явный capability gap, а не повод спрятать специализацию в learner.
04 / CRYSTALLIZER
Закон становится immutable executable data

Кристаллизуется весь оператор

Кристаллизатор не сжимает полный оператор в одну страницу. Он канонически собирает все исполняемые и проверочные части в один content-addressed bundle с единой identity.

Четыре изображения полного кристалла

ImageНазначениеЗапрет

Каноническая identity

law_id      = H(executable CanonicalOperatorIR without routing phase)
routing_id  = H(full RoutingImage)
artifact_id = H(compiler || VM ABI || law_id || ExecutionImage)
verifier_id = H(verifier ABI || VerifierImage)
proof_id    = H(ProofEnvelope)

bundle_id   = H(law_id || routing_id || artifact_id
                || verifier_id || proof_id)
Почему routing phase исключена только из law_id: независимо выученные маршруты могут привести к одному исполняемому закону. При этом полный bundle_id всё равно различает их routing evidence, verifier и proof provenance.
