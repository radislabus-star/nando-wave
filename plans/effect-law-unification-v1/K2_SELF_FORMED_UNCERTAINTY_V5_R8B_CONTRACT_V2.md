## 1. Exact Claim

R8B may prove only:

```text
one exact implementation commit
-> complete non-sealed package verification
-> one linked DevelopmentRehearsal process route
-> exact static and rehearsal control denominators
-> bounded resource execution
-> restart and cleanup readiness
-> R8B_FROZEN
```

It cannot prove the self-formed-uncertainty hypothesis, Natural K2,
natural-traffic transfer, Wave-causal grokking, product value, CPU savings or
deployment readiness.

## 5. Static Control Ownership

The R8B runner executes the existing `32 + 4 + 16` controls against the tested
commit. A static-control producer emits one process outcome for every canonical
ordinal. The unchanged control evaluator receives those measured outcomes and
emits three separately rooted receipts.

The aggregate requires exact IDs, order, expected named dispositions and
denominators. Panic, timeout, parse failure, omitted row, duplicate row or wrong
disposition is failure. A Cargo exit code alone is not a control receipt.

## 8. Fault, Restart And Cleanup

All existing mutating-transition faults and every legal journal prefix run
against the tested commit. The linked route additionally tests aggregate
publication failure before rename and after rename-before-directory-fsync.

On failure:

```text
individual suite logs and receipts retained
resource measurements retained
linked-route journal retained
published immutable aggregate retained if rename completed
unpublished aggregate temp removed
R8B_FROZEN absent unless every required receipt validates
```

Cleanup deletes only classified disposable rehearsal paths. Retained evidence,
failure evidence and owner receipts are immutable. The independent verifier
reopens and hashes the final tree and requires zero unclassified residue.
